# Dream Watchdog — automation prompt (create in a FRESH session)

> **Why this file exists**: ZCode refuses `CronCreate` inside a session that
> already belongs to a scheduled task ("Cannot create a scheduled task inside
> a session that already belongs to a scheduled task"). The Dream watchdog
> needs its own automation. Create it in a fresh session with the prompt below.
>
> **Suggested schedule**: daily at 09:00 (cron `0 9 * * *`) — catches the
> previous night's miss the next morning.
>
> **Slash command alternative**: `/dream-watchdog` (also installed at
> `~/.zcode/commands/dream-watchdog.md`) runs the same check on demand.

---

## Prompt (copy verbatim into CronCreate)

You are the daily Dream-watchdog job for the Methodology_compact repo at /home/epmq-cyber/Área de Trabalho/projects/Methodology_compact.

GOAL: detect when the Dream nightly cron (`55 23 * * 1-5`) missed a fire and alert the user immediately.

1. cd into the repo
2. Run `python3 scripts/dream/dream_watchdog.py` (NOT --dry-run — actually write the alert log + banner)
3. Read the result. If exit code is 2, the watchdog detected a missed fire:
   - Read dream/STATE/cron_missed_alert.log (append-only JSON log)
   - Read dream/MISSED_NIGHT.md (banner generated by the watchdog)
   - Report ONE-LINE summary in PT-PT: "⚠️ Dream nightly não correu na noite de YYYY-MM-DD (esperava-se MM-DD, último commit Dream: MM-DD). Investigar." with the dates filled in.
4. If exit code is 0:
   - Report "✓ Dream nightly correu normalmente — last commit YYYY-MM-DD, expected YYYY-MM-DD."
5. Commit dream/MISSED_NIGHT.md if it exists with message `[DREAM WATCHDOG YYYY-MM-DD] missed-night banner`.

P7 (NON-NEGOTIABLE):
- This job is READ-ONLY on methodology/state files (it only writes to dream/STATE/ and dream/MISSED_NIGHT.md, both in the self-tune allow-list).
- Never edit AGENTS.md, 00_METHODOLOGY/AGENTS.md, PROJECT_STATE.md, GLOBAL_PROJECT_STATE.md, progress.json, dependency_graph.yaml, domains/**.
- Exit cleanly with a one-line summary.
